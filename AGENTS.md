# Aggressively Refactor for Clean Architecture & Canonical Patterns

- This repo is a greenfield MVP projects that has no real users. Not even me is using this now.
- That means, always optimize for a canonical architecture not silent fallbacks, safe backward compatiblity layers
- When in doubt, aggressively refactor so that the codebase has one canonical, consistent pattern.
- Do not reach for hypothetical abstractions that may not come. Be clear, consistent, write clean code, maintain good separation of concerns.
- No God modules, Monoliths. Refactor them when you encounter to clean separate components with nice separation of concerns.
